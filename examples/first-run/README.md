# 第一次体验：原始台账 → 规则 → 处理结果 → 验收

这是公开的已解示例，适合先看工具怎么工作。想自己作答，请用 `practice.py` 生成独立练习。

## 跑一次

在工具包根目录运行（Python 3.10 或更新版本）：

```sh
python3 demo.py --output /tmp/etl-first-run-01
```

输出目录必须尚不存在。重复体验换个新目录，脚本不会清理旧结果。
不需要模型密钥、网络或 PyYAML，不会连接客户系统。

## 已给定的四格背景

这四格来自示例设计，不冒充真实客户确认，也不替代正式项目的四格确认。

| 格 | 示例事实与出处 |
| --- | --- |
| 客户与目标 | 虚构柜台收款核对；检查文件去重与金额换算。本页和 `source.json` 是输入契约 |
| 数据清单 | `source.json` 给四行输入；demo 生成一份原始 CSV，四列，无其他渠道数据 |
| 已发现问题 | T002 的两行内容完全相同；memo 四行均空且明确可空；见 `source.json` |
| 已问过谁 | 无真实访谈；规则由本示例设计者明示，见本页和输出 `cleaning/rules.json` |

给定处理规则：完全相同的输入只留一条；元用 Decimal ×100 转整数分；可空备注原样留空。
独立预期在运行前已给定：T001=1000 分，T002=2000 分，T003=5000 分；合计 8000 分。

## 打开哪些产物

| 输出位置 | 看什么 |
| --- | --- |
| `data/raw/receipts.csv` | 原始四行与哈希依据 |
| `artifacts/b01/run.json` | 输入、规则与程序版本 |
| `artifacts/b01/profile/profile_report.json` | 每列统计，空备注没有被当成丢值 |
| `artifacts/b01/cleaning/` | 规则 JSON 与三个接受记录 |
| `artifacts/b01/reconcile/` | 4＝3＋0＋1；每条原始记录的去向；重读原件后比较记录身份与值 |
| `artifacts/b01/metrics/metrics_run.json` | 8000 分／80 元，各自有单位 |
| `artifacts/b01/reports/coverage_notes.md` | 仅本次合成柜台台账，不推成全渠道销售 |
| `demo-verification.json` | 每个检查的命令、期望、实际、判断和原始输出 |

## 特意演示三种结果

1. 正常单位检查退出 0：在已给定契约范围内通过。
2. 演示者人为把单位改错，退出 1：证据冲突，不能交付。
3. 演示者未提供结果文件，退出 2：未完成验证，不能当成通过。

三个场景分别保存，不覆盖正常结果。第 0、1、4、7 步内置检查有实跑证据；本示例用 JSON 规则，未运行第 3 步 YAML 检查，也未调用大模型、取得客户反馈或完成十步项目验收。
