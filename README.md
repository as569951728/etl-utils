# etl-utils · 我的 ETL 工作包

> 一句话：**换项目时 clone 这个包，AI 就知道该怎么带我做完一单 ETL**——不用每次交代文件在哪、也不用依赖上一次会话的上下文。

## 包里有什么

| 文件 | 干什么 | 什么时候打开 |
| --- | --- | --- |
| **01-通用手册.md** | 主流程：0–9 步（数据段 0–5 ＋ 数据之后 6–9）、11 条指令（C0-A～C9-A）、4 件通用工具、验收话术 | **每天干活时用**：按台账"下一步"取编号，整段复制指令 |
| **03-生成定制手册话术.md** | 换客户时用：先让 AI 起草四格背景 → 生成定制手册 → 四招验收 | **新项目第一天** |
| **02-知识库-K1-K11.md** | ETL 常识汇编（K1–K11）＋"喂 AI 学习"的指令 | **换新会话、要让 AI 当角色时**先喂它 |
| **04-进度台账模板.md** | 进度台账空白模板（十行、四态、过关判据） | 新项目起步时复制一份 |
| **check.py** | 验收脚本骨架（纯标准库，无依赖） | 第 0 步、第 4 步的断言已写好，其余按步补 |
| **全景图-十步.svg** | 十步两段流水线全景图 | 给客户/导师讲流程时用 |

**不含任何客户数据。** 手册里的"实战校准"用的是课程沙盘（青禾）的合成数据，不是真实客户；换项目时按新客户重写。

## 三种用法

**① 新项目第一天（最常走这条）**

```sh
cd /path/to/new-project
git clone https://github.com/as569951728/etl-utils.git .etl-utils
```

然后在该项目根的 `AGENTS.md`（没有就新建）里加一行：

```
ETL 工具包在 .etl-utils/，按它的 README 与 AGENTS.md 执行；出定制手册前先读 03。
```

接着对 AI 说：**"读 .etl-utils，给这个客户出一份 ETL 手册"**——它会先起草四格背景给你确认，再生成手册。

**② 同一个项目，每天接着干**

只看 `04-进度台账模板.md` 复制出来的那份台账（或定制手册里的台账）的"下一步发什么"列，取编号去 `01-通用手册.md` 里整段复制指令。收工改三格：状态、产出物、判据。

**③ 换新会话，怕 AI 不懂 ETL**

先把 `02-知识库-K1-K11.md` 整份发给它，用文件里那段 📤 学习指令开场，让它复述要点，再干活。

## 三条不能破的规矩

1. **定制版不抄通用手册正文**——方法论只写编号（"发 C3-A"），**超过 600 行视为抄书，打回**；
2. **进度的 ✅ 只认"产出物存在 ＋ 判据勾完"**，不认"AI 说做完了"；
3. **四格背景先出草稿、我确认，再生成手册**——四格错了，整份手册全错。

## 更新约定

- 提交前跑一遍：`grep -rn "青禾\|客户名" .` 确认没有把客户信息带进来。
